# Voxel Craft --- документация для создателей модов

**Версия документации:** 1.0\
**Основа:** текущая сборка Voxel Craft 3D с WebGL, локальными мирами,
WebRTC P2P и IFrame-блоками.

> Эта документация описывает фактические точки взаимодействия,
> присутствующие в текущем HTML. Отдельного официального загрузчика
> модов/API-реестра в этой сборке пока нет, поэтому моды предполагаются
> как JavaScript-код, выполняемый в том же контексте страницы.

------------------------------------------------------------------------

## 1. Что такое мод в Voxel Craft

Мод --- JavaScript-код, который может работать вместе с игровым движком
и использовать его глобальные объекты и функции.

Основные области:

-   локальный игрок;
-   мир и блоки;
-   прицел и выбранный блок;
-   P2P-соединение;
-   чат;
-   сохранение миров;
-   интерфейс;
-   IFrame-медиа;
-   игровые действия и ввод.

### Важно

В движке используется обычный `<script>` без модульной системы. Поэтому
внутренние `const`, `let` и функции доступны коду, выполняемому в том же
глобальном JavaScript-контексте, но не являются стабильным публичным
API.

Для модов рекомендуется:

1.  не переопределять существующие функции;
2.  использовать уникальный префикс имён, например `MyMod_`;
3.  проверять наличие функции/объекта перед использованием;
4.  не изменять напрямую критические структуры, если можно вызвать
    существующую функцию.

# 2. Локальный игрок

Главный объект игрока:

``` js
P
```

Текущие поля:

``` js
P.x       // координата X
P.y       // координата Y
P.z       // координата Z

P.vx      // скорость по X
P.vy      // вертикальная скорость
P.vz      // скорость по Z

P.yaw     // поворот по горизонтали
P.pitch   // вертикальный угол взгляда
P.eye     // высота глаз

P.onGround
P.inWater
P.headWater

P.hit     // текущий объект под прицелом
P.hp      // здоровье
```

### Пример

Получить координаты:

``` js
function MyMod_playerPosition() {
  return {
    x: P.x,
    y: P.y,
    z: P.z
  };
}
```

Телепортировать локального игрока:

``` js
P.x = 20.5;
P.y = 40;
P.z = 20.5;
P.vy = 0;
```

После ручного изменения позиции рекомендуется обнулить `P.vy`, если
игрок не должен продолжить падение.

# 3. ID локального игрока

У каждого экземпляра игры есть:

``` js
PLAYER_ID
```

Он сохраняется в `localStorage` под ключом:

``` text
voxelcraft.playerId
```

Пример:

``` js
console.log(PLAYER_ID);
```

Используйте `PLAYER_ID`, если моду нужно отличать локального игрока от
удалённых игроков.

# 4. Удалённые игроки

Удалённые игроки хранятся:

``` js
MP.players
```

Это `Map`.

Получить количество игроков:

``` js
const count = MP.players.size;
```

Перебрать игроков:

``` js
MP.players.forEach(function(player, id) {
  console.log(id, player.nick, player.x, player.y, player.z);
});
```

Поля удалённого игрока:

``` js
player.id
player.x
player.y
player.z

player.yaw
player.pitch

player.hp
player.nick
player.color
player.t
```

### Найти конкретного игрока

``` js
const player = MP.players.get(id);
```

Если игрока нет, будет `undefined`.

# 5. Получение информации о прицеле

Текущий объект под прицелом:

``` js
P.hit
```

Когда блок найден, объект содержит координаты и нормаль стороны:

``` js
P.hit.x
P.hit.y
P.hit.z

P.hit.nx
P.hit.ny
P.hit.nz

P.hit.b
```

Где `b` --- ID блока.

Пример:

``` js
if (P.hit) {
  console.log(
    "Блок:",
    P.hit.b,
    "позиция:",
    P.hit.x,
    P.hit.y,
    P.hit.z
  );
}
```

Можно выполнить собственный raycast:

``` js
const hit = raycast(8);
```

Число `8` --- максимальная дистанция в блоках.

# 6. Работа с блоками

Основные функции:

``` js
getBlock(x, y, z)
setBlock(x, y, z, id)
```

## Получить блок

``` js
const id = getBlock(10, 30, 15);
```

Возвращается ID блока.

Воздух:

``` js
AIR
```

## Установить блок

``` js
setBlock(10, 30, 15, STONE);
```

Функция возвращает `true`, если изменение произошло.

Правильный вариант для мода:

``` js
if (setBlock(10, 30, 15, STONE)) {
  // блок действительно изменён
}
```

После изменения мира в мультиплеере желательно синхронизировать
изменение:

``` js
syncWorldEdit(10, 30, 15, STONE);
```

И сохранить мир при необходимости:

``` js
save();
```

``` js
const bd = blockDef(id);
```




# 8. Создание нового типа блока

В движке есть функция:

``` js
def(name, tiles, options)
```

Пример:

``` js
const MY_BLOCK = def(
  "Мой блок",
  TILE.BRICK,
  {
    hardness: 1.0,
    solid: true,
    opaque: true
  }
);
```

После вызова `def()` ID автоматически назначается движком.

**Не задавайте ID вручную.**

Используйте возвращённое значение:

``` js
const MY_BLOCK = def(...);
```

После этого:

``` js
setBlock(x, y, z, MY_BLOCK);
```

### Параметры

`name` --- название блока.

`tiles` --- один tile либо массив tile для граней.

`options` может содержать:

``` js
hardness
solid
opaque
liquid
glassy
```

# 10. Игровые действия

Основные функции:

``` js
doAction()
doBreak()
doPlace()
```

`doAction()` выполняет основное действие по текущему прицелу.

В текущей игре оно связано с использованием/разрушением объекта в
зависимости от выбранного элемента и состояния.

`doBreak()` ломает блок.

`doPlace()` устанавливает выбранный блок.

### Осторожно

Не вызывайте `doPlace()` или `doBreak()` в каждом кадре без
необходимости: это может создавать огромное количество изменений мира и
сетевых сообщений.

# 13. Отправка данных другому игроку

Основная функция:

``` js
sendRaw(message)
```

Она сериализует объект в JSON и отправляет его через DataChannel.

Пример:

``` js
sendRaw({
  type: "mymod:test",
  value: 123
});
```

Есть также:

``` js
broadcast(message)
```

Для текущей P2P-схемы это отправка сообщения через активный канал.

Пример:

``` js
broadcast({
  type: "mymod:event",
  value: "hello",
  id: PLAYER_ID,
  t: Date.now()
});
```

# 14. Приём собственных сообщений мода

Игровой обработчик получает JSON-сообщения через:

``` js
handleP2PMessage(raw)
```

Если мод добавляет собственный тип сообщения, ему необходимо добавить
обработку своего `type` в обработчик.

Пример идеи:

``` js
if (m.type === "mymod:event") {
  console.log("Получено:", m.value);
  return;
}
```

### Рекомендация

Используйте уникальный префикс:

``` text
mymod:
voxelmod:
creator_mod:
```

Например:

``` js
{
  type: "mymod:doorOpen"
}
```

Так разные моды меньше конфликтуют друг с другом.

# 16. Чат

Отправка сообщения:

``` js
sendChat("Привет!");
```

Сообщение проходит через P2P и отображается у игроков.

Текущий ник:

``` js
MP.nickname
```

Цвет:

``` js
MP.color
```

Вывод строки в локальный чат:

``` js
addChatLine({
  nick: "Мод",
  color: "#4ade80",
  text: "Сообщение"
});
```

Для текста от пользователя используется HTML-экранирование:

``` js
escapeHtml(text)
```

Не вставляйте пользовательский текст напрямую через `innerHTML`.

# 17. Атака другого игрока

В игре есть:

``` js
nearestPlayerInSight(maxDist, maxAngle)
```

Она ищет ближайшего удалённого игрока в направлении взгляда.

Пример:

``` js
const target = nearestPlayerInSight(3.2, 0.55);

if (target) {
  console.log(target.id, target.nick);
}
```

Также есть:

``` js
attackPlayer()
```

Она отправляет P2P-сообщение об атаке.

Модам рекомендуется не изменять HP другого игрока напрямую без
синхронизации.

# 18. IFrame Видео

IFrame-блок:

``` js
IFRAME_BLOCK
```

Данные URL хранятся:

``` js
IFRAME_DATA
```

Ключ:

``` text
x,y,z
```

Пример:

``` js
const key = iframeKey(10, 30, 15);
const url = IFRAME_DATA.get(key);
```

Установка URL:

``` js
setIframeData(10, 30, 15, "https://example.com/video");
```

Удаление URL:

``` js
IFRAME_DATA.delete(
  iframeKey(10, 30, 15)
);
```

# 19. Объединение IFrame-блоков

Соседние IFrame-блоки соединяются по 6 направлениям:

``` text
+X
-X
+Y
-Y
+Z
-Z
```

Поиск компонента:

``` js
iframeConnectedComponent(x, y, z)
```

Например:

``` js
const group = iframeConnectedComponent(10, 30, 15);
console.log(group);
```

Границы группы:

``` js
iframeGroupBounds(group)
```

Если рядом уже находится IFrame-блок с потоком, новый блок может
автоматически использовать тот же поток.

# 20. Локальные видео из галереи

Для локальных видео используется IndexedDB.

Хранилище:

``` text
voxelcraft_iframe_media_v1
```

Файл не отправляется другому игроку через P2P.

Это важно:

-   URL-ссылка может быть передана через P2P;
-   файл видео с телефона остаётся локальным;
-   другой игрок не получает сам файл из галереи.

Мод не должен пытаться передавать большие видеофайлы через обычный
`broadcast()`.

# 21. Сохранение мира

Главная функция:

``` js
save()
```

Получить снимок мира:

``` js
worldSnapshot()
```

Снимок содержит:

``` js
v
seed
caves
p
e
iv
```

Где:

-   `seed` --- seed мира;
-   `p` --- состояние позиции игрока;
-   `e` --- изменения блоков;
-   `iv` --- данные IFrame.

Миры хранятся в `localStorage`.

Основные ключи:

``` text
voxelcraft.worlds.v1
voxelcraft.currentWorld.v1
```

# 26. Время и игровой цикл

Главный игровой цикл использует:

``` js
frame(now)
```

`now` --- время браузера.

Для модов лучше использовать собственный таймер:

``` js
const timer = setInterval(function () {
  // логика мода
}, 1000);
```

или:

``` js
requestAnimationFrame(function tick() {
  // логика
  requestAnimationFrame(tick);
});
```

Не создавайте несколько бесконечных циклов при повторной загрузке мода.

# 30. Пример: проверка расстояния до другого игрока

``` js
function MyMod_distance(a, b) {
  const dx = a.x - b.x;
  const dy = a.y - b.y;
  const dz = a.z - b.z;

  return Math.sqrt(dx * dx + dy * dy + dz * dz);
}

MP.players.forEach(function(player) {
  const d = MyMod_distance(P, player);

  if (d < 5) {
    console.log("Рядом:", player.nick);
  }
});
```

# 31. Что нельзя делать без необходимости

Не рекомендуется:

-   перезаписывать `P`, `MP`, `World`, `R`;
-   менять `PLAYER_ID`;
-   вручную изменять `MP.players` для имитации сетевых игроков;
-   отправлять большие файлы через `broadcast()`;
-   вызывать `save()` сотни раз в секунду;
-   создавать бесконечные `setInterval`;
-   удалять чужие DOM-элементы;
-   вручную задавать ID блоков;
-   ломать существующий обработчик P2P-сообщений;
-   отправлять непроверенный пользовательский HTML через `innerHTML`.

# 32. Производительность

Voxel Craft работает в браузере и использует WebGL.

Для модов:

### Хорошо

``` js
setInterval(update, 100);
```

если логика действительно нужна 10 раз в секунду.

### Плохо

``` js
setInterval(update, 1);
```

без необходимости.

Также избегайте:

``` js
for (;;) {}
```

и тяжёлых вычислений каждый кадр.

Если нужно проверить большое количество блоков, разбивайте работу на
части.

# 33. Совместимость между модами

Используйте namespace:

``` js
window.MyMod = {
  version: "1.0"
};
```

Вместо:

``` js
window.update = ...
window.init = ...
```

Лучше:

``` js
window.MyMod = window.MyMod || {};

MyMod.init = function() {};
MyMod.update = function() {};
```

Для сетевых сообщений:

``` js
type: "mymod:event"
```

Для DOM:

``` text
#mymod-panel
#mymod-button
```

Для `localStorage`:

``` text
mymod.*
```

# 36. Минимальный чек-лист создателя мода

Перед публикацией проверьте:

-   [ ] Мод не падает при отсутствии P2P.
-   [ ] Мод не предполагает, что `P.hit` всегда существует.
-   [ ] Все пользовательские данные экранируются.
-   [ ] ID блоков берутся из `def()`, а не прописываются вручную.
-   [ ] Сетевые сообщения имеют уникальный `type`.
-   [ ] Большие данные не отправляются через P2P.
-   [ ] `save()` не вызывается слишком часто.
-   [ ] Мод не заменяет глобальные функции без необходимости.
-   [ ] DOM-элементы имеют уникальные ID.
-   [ ] Мод корректно работает, если другой игрок отсутствует.
-   [ ] Мод не уничтожает состояние мира при загрузке.

# 38. Важное замечание о будущей мод-системе

Текущая документация описывает **внутренний JavaScript API текущей
сборки**, а не отдельный стандартизированный Mod API.

Если в будущем будет создан официальный загрузчик модов, рекомендуется
сделать отдельный объект:

``` js
window.VoxelAPI = {
  player: {},
  world: {},
  blocks: {},
  network: {},
  chat: {},
  ui: {},
  events: {}
};
```

Тогда создателям модов не придётся напрямую обращаться к внутренним `P`,
`World`, `R` и другим структурам движка.

Это также позволит менять внутренний движок, сохраняя совместимость
старых модов.
